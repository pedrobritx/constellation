# Constellation workflow

Help Pedro move from a natural-language idea to useful software and resume another day. The ordinary Codex agent owns the integrated result. This is a product workflow, not a runtime, permission grant or assurance certificate.

## Establish the next useful move

Inspect the actual target repository, instructions, source/design, decisions and unfinished work before asking what is already known. For a new idea, understand the human task and recommend a small useful first slice; a named pilot is not a prerequisite. Never treat a projectless chat folder as an existing application repository.

Explain what exists, the recommended direction, its main trade-off and consequential unknowns in plain language. Ask only for missing information that materially affects behaviour, architecture, data, security, cost, user agency or something expensive to undo. Roughly five to eight initial questions can be a useful budget when context is missing, never a quota, questionnaire or lifetime limit. Ask at the relevant moment, reuse answers and recommend reversible defaults. Continue independent investigation while waiting; silence is not consent.

Converge on a brief product direction: who benefits, the first useful outcome, observable acceptance criteria, important exclusions, consequential choices and remaining uncertainty. Reuse an existing project record. Do not create a specification bureaucracy to begin work. Existing authorization covers reversible implementation within its scope; ask again only for a genuinely new consequential decision or required gate.

## Work with the project's commitments

Read [adoption.md](references/adoption.md) when determining governance, discipline adoption or terminology conflicts. Installation alone adopts no governance. For an already governed project, retain mandatory context, planner and review obligations; this workflow cannot bypass them. Keep its adopted request identity and source revisions connected to the product record.

Use only the knowledge needed for the current slice:

- Implementation or architecture: inspect existing boundaries, contracts and tests; use Axis when adopted or requested. Preserve the stack and favour the smallest reversible change that meets acceptance criteria.
- Interaction or visual work: use Meridian when adopted or requested. Start from supplied assets and current product identity. Resolve complete task states, keyboard/focus, responsive behaviour and localisation before considering visual polish. Stable design contracts remain the default; experiments need a deliberate choice.
- Changed trust boundaries, identities, permissions, sensitive data, dependencies or integrations: use Sentinel when adopted or requested. Inspect actual data flows and allow/deny paths; verify controls against concrete failure scenarios. A checklist is not security evidence.

For a selected capability, read its current AGENTS.md and required context at a recorded revision, then only task-relevant role/playbook material. Do not clone unselected libraries, copy policy catalogues or import every template. If required guidance is unavailable, disclose the gap and resolve it or obtain an approved alternative before dependent work; never silently claim coverage.

Disciplines are review lenses, not compulsory additional agents. Use one lead by default. Delegate only with authorization, actual host support and a useful bounded task; preserve shared interfaces and reconcile outputs. Describe review as independent only when it actually was.

## Deliver and leave a usable continuation

Build the authorized slice in the product repository. Revisit affected design, engineering and security decisions when interfaces change. Keep proposed checks distinct from commands actually run, their results, and direct or independent observations. Run relevant repository checks, inspect the integrated result and report failures or missing verification honestly. A skill, schema or planner pass cannot establish product correctness, accessibility or security.

Update concise project-owned continuity when meaningful state changes or work remains. Reuse existing status/handoff/decision conventions; otherwise keep one small durable note for direction, decisions and reasons, current revision/artifacts, actual checks, unresolved gates and the next useful action. No per-turn logs or duplicate tracking system. On resumption, verify current source and remote state before relying on old evidence.

Finish with the working result, inspectable artifacts, actual checks and practical limitations. Keep merge, publication, deployment, spend, destructive operations and security-posture gates under existing human/host authority. Stop dependent work at a real missing gate while completing other authorized work.
